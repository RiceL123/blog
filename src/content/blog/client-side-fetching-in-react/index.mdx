## Introduction
Data fetching is a crucial part of any application including [React](https://react.dev) apps. While server components is an interesting area to explore, for the sake of brevity, we will just focus on client-side fetching where data is just needed once on mount. We will assess the classic method of `fetch` inside an Effect and determine if it is an outdated approach by comparing it to other strategies.
## Methods
The methods will each be required to handle loading and success states with the data. We will use the same simple HTTP GET request from a cat facts API for each.
### useEffect
Using the [`useEffect`](https://react.dev/reference/react/useEffect) hook with an empty dependency array (`[]`) is the classic way to fetch data once on mount.

```jsx
import { useState, useEffect } from "react";

const CAT_FACT_URL = "https://catfact.ninja/fact";

export default function App() {
  const [isLoading, setIsLoading] = useState(false);
  const [catFact, setCatFact] = useState(null);

  useEffect(() => {
    async function fetchCatFacts() {
      setIsLoading(true);
      const response = await fetch(CAT_FACT_URL);
      const json = await response.json();
      setCatFact(json["fact"]);
      setIsLoading(false);
    }

    fetchCatFacts();
  }, []); // empty dependency array to run once on mount

  if (isLoading) return <p>Loading...</p>;
  return <p>{catFact}</p>;
}
```

> **Note**:
> You may see a double render and/or 2 requests in the network tab in development due to React's `StrictMode`. This is expected as `StrictMode` is designed to help catch potential issues so please don't remove it. In production, it will only fetch once.

**Benefits:**
- Works with vanilla React v16.8+ (Feb 2019)
- Provides full control over the fetching process

**Caveats:**
- Manual state management of loading, error and success states
- Imperative 
- Require
#### Custom Hook
To improve code organisation and reusability, we can extract the fetching logic to a custom hook.

```jsx
import { useState, useEffect } from "react";

const CAT_FACT_URL = "https://catfact.ninja/fact";

function useCatFact() {
  const [isLoading, setIsLoading] = useState(false);
  const [catFact, setCatFact] = useState(null);

  useEffect(() => {
    async function fetchCatFacts() {
      setIsLoading(true);
      const response = await fetch(CAT_FACT_URL);
      const json = await response.json();
      setCatFact(json["fact"]);
      setIsLoading(false);
    }

    fetchCatFacts();
  }, []);

  return { isLoading, catFact };
}

export default function App() {
  const { catFact, isLoading } = useCatFact();

  if (isLoading) return <p>Loading...</p>;
  return <p>{catFact}</p>;
}
```

> **Note**:
> Custom Hooks require 'use' as a prefix (e.g. `useCatFact`)

**Benefits**:
- Works with vanilla React v16.8+ (Feb 2019)
- Separation of fetching and UI logic
- Reusable hooks across components

**Caveats**:
- Same caveats with `useEffect` + `fetch` such a manual state management
### Suspense + use
The [`React.use`](https://react.dev/reference/react/use) API was introduced in [React v19](https://react.dev/blog/2024/12/05/react-19#new-feature-use) to read resources in render. When `use` is passed a promise, React will [Suspend](https://react.dev/reference/react/Suspense) until that promise resolves.

```jsx
import { Suspense, use } from "react";

const CAT_FACT_URL = "https://catfact.ninja/fact";

function CatFact({ catFactPromise }) {
  const catFact = use(catFactPromise); // suspends until promise resolves
  return <p>{catFact}</p>;
}

export default function App() {
  const catFactPromise = fetch(CAT_FACT_URL)
    .then((res) => res.json())
    .then((json) => json.fact);

  return (
    <Suspense fallback={<p>Loading...</p>}>
      <CatFact catFactPromise={catFactPromise} />
    </Suspense>
  );
}
```

> **Note**:
> - Suspense does not detect when data is fetched inside an Effect or event handler - it's designed for resources consumed directly during render
> - `React.use` does not support promises created in render. The promise should be stable


**Benefits**:
- Works with vanilla React v19+ (Dec 2024)
- Idiomatically integrates with built-in `Suspense` for declarative loading states
- Leverages modern React concurrent rendering capabilities

**Caveats**:
- Requires an `ErrorBoundary` or alternative value with `Promise.catch` for [rejected promises](https://react.dev/reference/react/use#dealing-with-rejected-promises)
### SWR
[SWR](https://swr.vercel.app) (derived from '`stale-while-revalidate`') is a lightweight data fetching and caching library that shares similarities with TanStack Query but focuses on simplicity.

```jsx
import useSWR from "swr";

const CAT_FACT_URL = "https://catfact.ninja/fact";

const fetcher = (url) => fetch(url).then((res) => res.json());

export default function App() {
  const { data, isLoading } = useSWR(CAT_FACT_URL, fetcher);

  if (isLoading) return <p>Loading...</p>;

  return <p>{data["fact"]}</p>;
}
```

**Benefits**:
- Designed to be straightfoward and easy to use
- Implements `stale-while-revalidate` along with other features like 

**Caveats**:
- ~8kb bundle size
- Requires learning an external library
### TanStack Query
[TanStack Query](https://tanstack.com/query) (formerly `react-query`) is a full-featured asynchronous state manager. It has been an incredibly popular solution for both serious and simple application with its robust feature set.

```jsx
import { useQuery } from "@tanstack/react-query";

const CAT_FACT_URL = "https://catfact.ninja/fact";

function useCatFact() {
  return useQuery({
    queryKey: ["cat-fact"],
    queryFn: async () => {
      const response = await fetch(CAT_FACT_URL);
      return await response.json();
    },
  });
}

export default function App() {
  const { data, isLoading } = useCatFact();

  if (isLoading) return <p>Loading...</p>;

  return <p>{data["fact"]}</p>;
}
```

> **Note**:
> Tanstack Query requires a `<QueryClientProvider>` to be set up higher in the component tree to manage the cache for your queries

**Benefits**:
- Comprehensive set of features for caching, refetching, pagination, background updates and more
- Automatic state management for handling loading error success states
- Performance optimisation with caching and parallel queries

**Caveats**:
- ~20kb bundle size
- Requires learning an external library, though very well documented
## Conclusion
Choosing the right data fetching strategy for simple fetch once on render queries depends on multiple circumstances
- **`useEffect`**: manually manage states
- **`Suspense` + `use`**: idiomatic and performant React v19+
- **SWR**: lightweight caching solution
- **TanStack Query**: complex applications

Overall, I would recommend avoiding `fetch` in `useEffect` and instead would point you to the `use` API or external libraries.
